## The 15 Golden Rules of Dossier Presentation

### 1. High-Contrast Typography (Zero "Green Flood")
- **Rule:** Body text and bold terms (`**text**`, `<strong>`) must be rendered in crisp, high-contrast neutral color (`var(--text-primary)`, `#f8fafc` in dark mode, `#0f172a` in light mode).
- **Prohibition:** NEVER color general bold markdown green (`#10b981` / `text-[#10B981]`).
- **Accent Exclusivity:** Vivid emerald green is strictly reserved for:
  - Quantitative status badges (e.g., `🟢 Clean & Corroborated`, `Passes Lynch Test`, `Margin Buffer`).
  - Cash flow curve lines and active data dots.
  - Valuation summary cards and active KPI callouts.
  - Border indicators for active section headings and callout boxes.

### 2. Chapter Hierarchy vs. Raw Engine Markers
- **Rule:** Output files must NEVER contain raw execution engine markers like `## [Step 1 Output]`, `## [Step 2 Output]`, or bracketed prompt tags.
- **Mapping Requirement:** Map every step to its institutional title using `STEP_CHAPTER_TITLES`:
  - `Part 1: Financial Forensics & Capital Allocation Discipline`
  - `Part 2: Operational Engine & Market Analysis`
  - `Part 3: Normalized Owner Earnings & Cash Flow Integrity`
  - `Part 4: Structural Moat Architecture & Antifragility`
  - `Part 5: Qualitative Filing Audit & Hidden Assets`
  - `Part 6: Valuation Floor: Zero-Growth Earnings Power Value (EPV)`
  - `Part 7: Valuation Engine: Probabilistic Owner Earnings DCF & Reverse DCF`
  - `Part 8: Valuation Synthesis & Sensitivity Matrix`
  - `Part 9: Preliminary Investment Thesis & Lynch Archetype`
  - `Part 10: Stress Test: Red Team Forensic Short Attack`
  - `Part 11: Definitive Verdict, Resolution & Monitoring Dashboard`
  - `Part 12: Forensic Audit & Fact-Check Crosscheck`

### 3. Obsidian Knowledge Graph YAML Frontmatter & Cockpit Ground Truth
- **Rule:** Every exported `.md` file must prepend structured YAML frontmatter starting at Line 1:
  ```yaml
  ---
  ticker: TICKER
  company: "Company Name, Inc."
  period: Q1-27
  market_price: 188.75
  intrinsic_value: 120.35
  margin_of_safety: "-56.8% (Overvalued)"
  decision: PASS
  lynch_profile: "Fast Grower"
  user_cost_basis: 112.77
  user_portfolio_weight: "7.71%"
  date: 2026-10-04
  ai_model: gemini-3.8-flash
  tags:
    - value-investing
    - valuation-dossier
  ---
  ```
- **Parsing Guard:** `parseBlocks()` in `MarkdownView.tsx` must explicitly skip this frontmatter block so raw YAML lines are never rendered into the HTML document or React DOM.
- **Portfolio Weight Normalization:** When generating frontmatter, ensure existing percent signs are stripped before appending `%` (e.g., `user_portfolio_weight: "5.78%"`), preventing `"5.78%%"`.
- **Cockpit Frontmatter Ground-Truth Invariant:** The standalone HTML executive cockpit (`extractExecutiveCockpit` in [`src/utils/googleDocs.ts`](file:///c:/Users/Ronald/antigravity/Value-Investing-Terminal/src/utils/googleDocs.ts)) must prioritize Line-1 YAML frontmatter (`market_price:`, `intrinsic_value:`, `user_portfolio_weight:`, `user_cost_basis:`, `decision:`, `lynch_profile:`) as the absolute single source of truth for the current share price, intrinsic value, cost basis, portfolio weight, and Peter Lynch profile. It must NEVER parse portfolio weight using loose regexes like `\bWeight\b` across the body (which can accidentally pick up unrelated percentages like DCF scenario weights or 3-Year CAGR weights). Also, `TRIM` is strictly eliminated under the Never-Trim Compounding Doctrine; any legacy `TRIM` or `MAINTAIN` directive is unconditionally normalized to `HOLD`.
- **Lynch Archetype Extraction Contract:** When resolving `lynch_profile:` for YAML frontmatter and HTML pill cards, extractors must strictly follow this precedence hierarchy:
  1. Line-1 YAML frontmatter (`lynch_profile:`).
  2. The canonical Part 9 GFM table row (`| **[Archetype Name]** | **ACTIVE ARCHETYPE** |`).
  3. Multi-word regex alternations where composite labels (`Cyclical Compounder | Pure Commodity Cyclical | Wide-Moat Stalwart`) precede single-word prefixes (`Cyclical | Stalwart`) to eliminate premature truncation.

### 4. Floating Quick Jump Navigator De-Cluttering
- **Rule:** The interactive floating TOC drawer (`#toc-menu` / `sectionNav`) must offer high signal-to-noise ratio.
- **Checklist Filter:** Subheadings matching `Step Summary Checklist`, `Verification Checklist`, or `Section X Verification Checklist` must be filtered out of `sectionNav`.
- **Active Scrollspy:** The floating pill button must update dynamically with the active section title, highlighting the active TOC link with an emerald accent indicator.

### 5. Heading Architecture & Accents
- **Level 2 Headings (`.dossier-h2`):**
  - Styled with a vertical emerald indicator: `border-left: 4px solid var(--accent-emerald); padding-left: 12px; margin-top: 32px; font-weight: 700;`.
- **Level 3 Headings (`.dossier-h3`):**
  - Styled with neutral `color: var(--text-primary); font-weight: 600;`, eliminating the inverted hierarchy where subheadings were previously more vivid than main headings.

### 6. Zero-Typewriter, Zero-Box, Zero-Slider & Standardized GFM Table Rules
- **Rule:** Monospace code blocks containing ASCII art borders (`+----+----+`, `====`, `----`), Unicode box characters (`│`, `┌`, `└`), typewriter space-aligned matrix text, typewriter slider bars (`$0.00 ─── [$X] ───>`), ASCII arrows (`──>`), or text-based progress bars / hash bars (`[#####]`, `[###]`) are strictly forbidden.
- **Mandatory GFM Conversion:** All tabular data, segment direct contributions, competitor market shares, credit portfolio integrity checks, and historical trajectory series must be converted into GitHub-Flavored Markdown pipe tables:
  ```markdown
  | Dimension / Metric | Audited Value | Source Citation |
  | :--- | :---: | :--- |
  | Operating Cash Flow | $598.60M | Form 10-Q, p. 5 |
  ```
- **Obsidian GFM Pipe Table Parsing Invariance:** Every table must have a header line and separator line (`| :--- | :---: |`). Single-pipe pseudo-headers (`| TITLE |`) and missing separator rows (`| --- |`) are strictly normalized via `normalizeSinglePipeTables()` so Obsidian never collapses them into monospace typewriter text.
- **Piped Bullet Prohibition:** Never format comparative tables or peer cards as bullet points with pipe delimiters (`* **PEER** | Col | ...`). Piped bullets must be transformed into standard GFM pipe tables.
- **Bullet-Prefixed Tree Normalization:** Any LLM generation employing tree-branch notation (`* ├─`, `* ├──`, `* └─`, `* └──`) must be converted into clean, standard indented Markdown bullet hierarchies (`  * **Key:** Value`). Inline arrows (`──>`) are converted to clean Unicode arrows (`➔`).
- **Exhaustive Box Divider Stripping:** Box-drawing dividers containing `[─\-+┼│|├┤┬┴┌┐└┘║═╦╩╬]` (such as `* **─────────────┤**`) are completely stripped, preventing stray bulleted lines across the document.
- **Mandatory Standard Table Schemas & Aesthetic Layouts:**
  1. **Competitor Moat & Valuation Radar (Part 2, Sec 1.4):** 7 columns: `| Competitor / Peer | Gross Margin | Operating Margin | ROIC | EV / True FCF | EV / Owner Earnings | Net Cash / Mkt Cap |`.
  2. **DCF Scenarios & Projections (Part 7, Sec 2):** 4 columns: `| Valuation Scenario | Probability Weight | Per Diluted Share Value | Implied MoS vs. Market Tape |`. (Zero Unicode box dividers `│`).
  3. **Lynch Category Continuum (Part 9, Sec 1.1):** 3 columns: `| Peter Lynch Archetype | Classification Status | Empirical Operational Validation |`. (Zero typewriter continuum sliders `──>`).
  4. **Target Buy Price Bands (Part 9, Sec 1.4):** 4 columns: `| Target Buy Price Band | Price Range ($) | Margin of Safety Discount | Allocation Directive |`. (Zero typewriter price sliders).
  5. **Definitive Investment Verdict (Part 11, Step 4):** 2 columns: `| Decision Parameter | Audited Portfolio Verdict |`.
  6. **Symmetrical Balance Sheet Synthesis (Part 5, Sec 2):** 3 columns: `| Off-Balance-Sheet Vector | Valuation Spread ($M) | Balance Sheet Impact |`. (Subtotals and status badges).
  7. **Chapter Preamble Summaries (Parts 2, 3, 7, 8):** 4 columns: `| Strategic Parameter | Audited Economic Anchor | Strategic Parameter | Audited Economic Anchor |`.
- **Obsidian Indented Code Block Elimination:** Accidental leading indentation (4+ spaces) on non-code lines is programmatically stripped (`text.replace(/^[ ]{4,}(?=[A-Z0-9#\*\|])/gm, "")`) so Obsidian never wraps preamble sections or headers in dark monospace `<pre><code>` blocks.
- **Table Cell Alignment & Layout Contract:** 
  - Standard numeric-only columns right-align (`.cell-numeric`).
  - 2-column key-value and verdict tables assign `.cell-verdict-val` (`text-align: left !important; padding-left: 1.5rem !important;`), preventing jagged zig-zag misalignment where numeric figures right-align against centered text cells.
- **Parser & Chart Resilience:** 
  - `parseNumeric` must strip markdown asterisks (`**`), code tags, and parse accounting negatives like `**($19.00)**` properly without NaN-collapse.
  - Cash flow trend charts must never bind percentage/margin rows (e.g. `Owner Earnings Margin (%)`) to absolute dollar trajectories (e.g. `Normalized Owner Earnings`), preventing flat-line zero collapse.
  - **Revenue Segment Mix Visualizer (`<SegmentMixChart>` / `renderSegmentBarHtml`):** Product and geographic segmentation tables trigger `chartType === 'segment'`, rendering a stacked horizontal distribution bar with proportional color fills and percentage badges. Column resolvers must strictly prioritize revenue contribution / share columns (`% of Total Revenue`, `Share %`, `Revenue Share`) over velocity columns (`YoY Growth Rate (%)`, `CAGR (%)`), and exclude sub-component rows starting with dashes (`—`, `–`, `-`) to maintain part-to-whole 100% integrity.
  - **Moat Leaderboard Deduplication & Dynamic 5-Axis Radar SVG (`renderCompetitorRadarSvg`):** The Competitor Radar SVG polygon in `src/utils/googleDocs.ts` computes its 5-axis polygon coordinates (`Gross Margin`, `Operating Margin`, `ROIC`, `FCF Yield`, `Balance Sheet`) dynamically from the parsed Moat Leaderboard `rows` (averaging peer rows vs. the target company) and transitions directly into the clean GFM comparative table. Redundant visualizer card grids (`renderLeaderboardHtml` / "Moat & Peer Leaderboard Benchmark") that replicate table rows are strictly eliminated.
  - **Live React UI Visualizer Parity (`src/components/MarkdownView.tsx`):** `ValuationSpectrumChart` dynamically interpolates `Current Market Quote ($${currentPrice.toFixed(2)})` (never hardcoded placeholder prices), and `FlywheelViewer` detects `NO ORGANIC FLYWHEEL` / `LINEAR VALUE CHAIN` headings to render the horizontal 5-stage Linear Value Chain pipeline (`TERMINAL NODE` Stage 05 and `AUDIT VERDICT: LINEAR VALUE CHAIN / DISCRETIONARY CAPITAL ALLOCATION` banner) matching standalone HTML and Obsidian Markdown outputs.
  - **Dynamic Sanitization Guard:** `dossierFormatGuard.ts` must parse metrics and thresholds dynamically from LLM output. Hardcoding specific company figures into guard regexes is strictly forbidden.
  - **Audit Finding Badge & Table Width Invariance:** Programmatic HTML converters and guards must strictly apply `.audit-badge` only to concise, standalone audit verdicts (`cleanCell.length <= 30`, e.g. `PASS`, `FLAG`, `BREACH`, `FAIL`, `CLEAN`, `CORROBORATED`). Explanatory trigger conditions or sentences beginning with `"Flag if..."`, `"Pass if..."`, or containing conditional clauses (`\bif\b`) must NEVER be converted into audit badges. This preserves natural line wrapping and prevents table column blowout or off-screen clipping. All table cells (`th`, `td`) enforce `overflow-wrap: break-word` and `word-break: normal`.

### 7. Dual Compounding Architecture (Flywheel vs. Linear Value Chain), Zero Premature Flywheels & Mandatory Falsification Audit
- **Zero Premature Flywheels:** Compounding loops/flywheels are STRICTLY FORBIDDEN in Part 1 or Part 2 (e.g., Section 1.1 Core Business & Economic Engine). Section 1.1 must detail empirical operational pillars, never a premature compounding loop. Flywheels/value chains are synthesized exclusively in Part 4 Section 1.7 after forensic balance-sheet and moat audits.
- **Mandatory Flywheel Falsification Audit:** The terminal does NOT force or invent artificial flywheels for linear commodity processors or cyclical manufacturers. If a business lacks an organic compounding loopback, Section 1.7 must explicitly state `#### 1.7 Compounding Architecture: LINEAR VALUE CHAIN / CYCLICAL COMMODITY (NO ORGANIC FLYWHEEL)` and detail its operational constraints.

- **Dual Architecture Parity:**
  - **Branch A: Organic Compounding Flywheel (MELI, V, MA):**
    - *Obsidian Markdown:* `flowchart TD` with rounded nodes (`rx:8, ry:8`) and highlighted closed-loop return edge:

  - **Branch B: Audited Linear Value Chain (STRL, CALM):**

### 8. Standalone Single-File Portability & Mobile UX Mandates
- **HTML Dossier:** Must be completely self-contained.
- **Zero External CDNs:** Embedded fonts (Inter, JetBrains Mono), embedded CSS variables, inline SVG charts, and base64 WebP images.
- **Theme Persistence:** Dark mode (`[data-theme="dark"]`) and Light mode persisted in `localStorage`.
- **Print to PDF:** Dedicated `@media print` rules stripping toolbars and enforcing clean page breaks.
- **Mobile Software Keyboard Prevention Mandate:** Floating Quick Jump Navigator (`#toc-menu`) must never include text search/filter inputs (`<input>`) or automated `focus()` calls. On mobile touchscreens, autofocus summons the software keyboard, obstructing the navigation menu and displacing the viewport. The menu is strictly a tap-to-select anchor list.
- **Mobile Header & Summary Viewport Containment:** Executive cockpits, KPI grids, and header containers must strictly enforce `width: 100%`, `overflow-x: hidden`, and word-breaking to prevent horizontal viewport spilling on small phone screens (<= 480px).

### 9. Zero Raw TeX Math & Formula Card Encapsulation
- **Rule:** Output files must NEVER leak raw LaTeX syntax (`\frac`, `\Delta`, `\quad`, `\mathbf`, `\{,\}`, `$$...$$`).
- **Plain-Text Formulas:** All mathematical expressions must be converted into clean, plain-text typography (`(n / d)`).
- **Valuation Schedules:** Financial schedules (`Valuation Range Visualization:`, `Synthesized Intrinsic Value Weighting Bridge:`, `Target Buy Price Band Architecture:`) must be encapsulated into styled `.formula-card` components (`<div class="formula-card">...</div>`).

### 10. Code Fence Inversion & Empty Block Guard
- **Rule:** An unclosed code block at mid-document inverts the entire parser (prose becomes code, and code becomes prose).
- **Auto-Closure Requirement:** Financial schedules starting with code fences must be closed before section dividers (`---` or `##`).
- **Double-Fencing Prohibition:** Never wrap schedules that are already inside backticks. Use negative lookbehinds `(?<!\`\`\`[^\n]*\r?\n)` to guard against double-wrapping.
- **Empty Fence Stripping:** Empty code blocks (`\`\`\`\s*\`\`\``) must be systematically stripped before HTML rendering.

### 11. Buy-Side Desk Nomenclature & Zero-Academic-Citation Mandate
- **Rule:** Dossiers and prompts represent an institutional buy-side desk's audited valuation framework, NOT a business school textbook review. All academic textbook citations, creator name-drops, and professor titles must be completely omitted.
- **Standardized Mapping:**
  - *Greenwald EPV* ➔ **Earnings Power Value (EPV)** or **Zero-Growth EPV Floor**.
  - *Greenwald Asset Value Reproduction* ➔ **Net Asset Reproduction Floor (ARV)** (Permanently eliminated under Cash-Flow Sovereign Model).
  - *Sloan Accrual Ratio* ➔ **Balance Sheet Accrual Ratio** or **Earnings Quality Spread**.
  - *Beneish M-Score* ➔ **Earnings Manipulation Risk Index**.
  - *Graham-Buffett-Greenwald Framework* ➔ **Cash-Flow Sovereign Valuation Framework** or **Proprietary Valuation Triad**.
  - *Mauboussin / Rappaport Reverse DCF / Expectations Investing* ➔ **Market-Implied Expectations Reverse DCF**.
  - *Schilit / O'glove Forensic Shenanigans* ➔ **Forensic Accounting & Earnings Quality Audit**.
  - *Thorndike Capital Allocation / Buybacks* ➔ **Capital Allocation & Share Repurchase Discipline**.
  - *Bill Gurley / Hamilton Helmer Moat Scorecard* ➔ **Platform Network Effects & Structural Moat Scorecard**.
- **Enforcement:** Enforced in prompt bodies, system prompts, and programmatically scrubbed in `dossierFormatGuard.ts` so no academic creator tags ever leak into final `.md` or `.html` deliverables.

### 12. Clean Environment & Ticker Isolation Guard
- **Strict Prohibition:** Output dossiers and intermediate drafts must NEVER contain lingering sections, financial tables, or peer commentary from another company evaluated in an earlier session.
- **Section-Preservation Guardrail:** The markdown renderer and format guard must pre-flight snapshot all 12 canonical `## Part X:` headings before applying any transformations. If any heading is dropped or swallowed, all mutations must immediately abort.
- **Frontmatter Ground Truth Isolation:** Frontmatter extraction must strictly parse the active evaluated company and Part 12 portfolio directives, stripping any legacy draft frontmatter to prevent circular verdict defaults.

### 13. Synchronized Filename Convention & Multi-Model Provenance Mandate
- **The Multi-Model Collision Trap:** When the same company and fiscal period are evaluated across different frontier AI models (e.g. comparing `gemini-4-argon` vs. `gemini-3.8-flash`) on the same trading day, output files must never collide or overwrite each other.
- **Harmonized Filename Schemas:**
  - **Obsidian Markdown (`.md`):** `${tickerStr} ${periodStr}_Complete Doc_${modelName}_${formattedDate}.md`  
    *(e.g., `MELI Q2-26_Complete Doc_gemini-4-argon_10-15-26.md`)*
  - **Standalone HTML Dossier (`.html`):** `${cleanTicker} ${cleanPeriod}_Valuation_Dossier_${modelName}_${formattedDate}.html`  
    *(e.g., `MELI Q2-26_Valuation_Dossier_gemini-4-argon_10-15-26.html`)*
- **Universal Enforcement Across Delivery Channels:**
  - Client-side browser download button (`handleExportHtml` in `src/App.tsx`).
  - Server export endpoint (`/api/session/export-html` in `server.ts`).
  - Automated post-run email/telegram notification attachments (`runStepProcessor` in `server.ts`).

  - Runner and test orchestrators (`scripts/run_calm_terminal.ts`).
- **Date Formatting:** Strictly two-digit month, day, and year separated by hyphens (`MM-DD-YY`, e.g. `10-15-26`), matching the canonical Markdown document convention.

## Automated Verification Workflow

Whenever updating or auditing dossier output files, run the automated verification script:

```powershell
npx tsx .agents/skills/dossier-curator/scripts/verify_dossier.ts "<path-to-markdown-or-html-file>"
```

### Self-Healing Checklist
If an output file exhibits flaws:
1. Run `cleanMarkdownForRendering(markdown)`:
   - Decomposes nested LaTeX fractions via the recursive multi-pass loop.
   - Cleans TeX operators (`\Delta` ➔ Δ, `\times` ➔ ×, `\cdot` ➔ ·).
   - Auto-closes unclosed schedule blocks and strips stray trailing fences at EOF.
   - Strips empty code blocks (`\`\`\`\s*\`\`\``) that cause empty `<pre>` tags.
2. Verify that `parseBlocks()` skips YAML frontmatter.
3. Check `googleDocs.ts` CSS to guarantee `.text-strong` has `color: var(--text-primary)`.
4. Re-compile and verify build with `npm run build`.
